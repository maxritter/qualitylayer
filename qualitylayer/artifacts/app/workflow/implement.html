In short

One board from the first card to the last; what the agents need stays in their file.

  • Cutting the Plan comes first. The slices appear on the board as they are written, and the first slice starts building as soon as its cards exist
  • One board. Slices with task cards open each time you enter Implement, and you can collapse them while you read. Past five finished slices, their counted group also opens by default. A task opens to one sentence, then Files, Test first and Done when
  • Proof order stays with the agents. They run each Done means step as soon as its slice is in; you see the points proven on Verify
  • Decided while building, one closed fold. A row's tag says its kind: Build order or Plan amended. Only a change to the Plan you approved is an amendment; a task card that changes is the agents' business
  • Program design, a closed fold at the bottom
  • A card carries Notes: the one or two findings and pitfalls this task needs, each with a link to the helper's report
  • The build starts at approval in one of three ways: Build here from the Plan, Keep this conversation, Another session or agent
  • The limit line: when an agent hits its usage limit, the reason, the reset time and whether QualityLayer resumes by itself. From it, Continue in another agent picks the task up where it stopped

What the agent writes

One Implement text: the agent cuts the Plan into slices and cards, then builds.

PartWho writes it, and how
Cutting the PlanThe agent, first: slices and cards, then the build. A small task's single slice is written and built in one pass.
Task cardsThe agent, in agents/02-implement.md: Objective, Files, Notes, Test first, Done when. Notes hold what this task needs from the reading, in one or two lines, with its link. Files list changed repository source (tests, fixtures, docs and lasting models), never task records, evidence or drafts. Use none for evidence-only qualification without source changes; put inspected paths in Read only. The Plan's Constraints apply to every card without being repeated on it. Parallel builders get separate Files. A deferred file belongs to the slice that will commit it. The repository’s rules govern whether task records are committed.
Proof orderThe agent puts each step after the slice that makes it possible and records a command that proves the whole expectation. Focused checks show narrower results in records/checks.md, under Files › Records › Checks. If only you can do a step, the agent names it when handing the build to Verify and asks you there.
Summary and SlicesQualityLayer: one line of counts and the slice table.
Decided while buildingQualityLayer, from the record: one line per decision that touches what you approved or the order of the build, with its kind. A card that turns out to need another file is the agent's own change, written on the card; it is no amendment.
Program designThe agent: a headline per decision about how the code is shaped. Where each module lives stays in the agents' file.
StatusQualityLayer: a card ticks when its check passes, from the first slice, and "N under way" shows while helpers work. A commit never holds the status back.
QuestionsRare. A matter only you can settle is asked once, and the build runs on.
HelpersThe lead builds a small change directly. On a larger task, it delegates cohesive slices that can proceed independently. Each helper owns its files, checks and handoff. The lead reviews and integrates their work. Dependent work waits for its checked prerequisite.
