Who reads what

What each reader is handed. Its size is measured in the benchmark.

ReaderWhat it reads
YouThe concise Plan page before you approve; the Verify page at the end
The plannerNothing to read back: it writes the Plan in the session that read the code
The Plan's reviewerThe two Plan files. Native Plan and security reviews use the configured judge model at high effort. Artifact checks use the configured design model at high effort.
The buildThe two Plan files; it writes the cards itself
The judge, each roundThe people's Plan, the Constraints and the task cards, and on a later round the lines that failed (rechecks skip whole-diff test authorship). It records verdicts live with qualitylayer verdict and renders/validates its iteration block with qualitylayer verdict finish. When the person requires no file changes, it keeps normal access and returns its review/verdicts and test/doc proposals for verbatim recording.
The build's reviewerThe same, and the diff without generated files

Copy and share

  • Copy. A step page copies as Markdown, or with pictures for Confluence, Docs, Notion and Word. Copy for an agent includes the agent notes and the Implement check results.
  • Get approval sends the same file and tracks its revision, so an approval or a comment from outside lands on the right version. On the Plan it sends 01-plan.md; on Verify, 03-verify.md as the pull request description.
  • No sharing with teammates inside QualityLayer. Other people read and approve on the systems they already use.
