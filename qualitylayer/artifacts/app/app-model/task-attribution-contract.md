# Task attribution across native working directories

A native agent may start in checkout A and explicitly join a QualityLayer task
in checkout B. Its authoritative workflow binding selects the task. Its native
working directory interprets relative tool paths. The task's recorded checkout
selects Git, file journals and the App's Changes view. Before using a recorded
checkout, bounded Git discovery must still match the project's common directory.
When Git returns the physical spelling of a recorded alias, the task keeps its
registered project identity. A reused path belonging to another repository grants no task authority.
No task or checkout is silently moved, and ordinary CLI commands retain their explicit-checkout rules.

Cost follows the exact bound native sessions and their verified helper lineage,
from each task claim until that session's next task assignment. Earlier session
history and an unrelated session in the same native directory do not belong to
the task. Replayed calls and parent/helper copies count once. The task's stage
events allocate lead usage; each helper retains the existing starting-step rule
and names its actual native agent. An incidental legacy cost note cannot claim
another checkout without a current workflow binding or recorded claim proof.
Live reads and reloads give the same totals, including work recorded after the
page opened. No approximation or partial-data label substitutes for attribution.

Live status, progress and file observations follow the same existing binding.
Exact native file receipts for absolute and relative paths inside B reach the
App's Changes view. Literal shell `cd` hints stay in B's journal with the
existing no-exact-diff boundary; A's unrelated edits stay out. Stopped state, task retirement and rebinding keep their
existing authority. A binding does not expire merely because an active native
process has been running for a long time.

A small local current-binding index accelerates observation. It is derived from
and checked against the per-project workflow binding's task and generation;
it grants no task authority itself. Rebinding replaces it atomically, stale or
ambiguous records cannot resurrect a prior task, and retirement removes the
matching entry. Existing running sessions use a bounded lookup of their exact
saved assignment history, without scanning every project or transcript.

The index reuses the existing 512 native-session storage bound. Bind/adoption
maintenance may remove demonstrably orphaned entries; active authority is never
evicted for space or age. A full active index refuses admission before a new
session or claim is shown as established. Existing keys remain rebindable.
