Agents that did not write the code check every **Done means** point and fix what fails. Then the same page becomes your review: the code first, then what changed and each point as it ran. A failure is never marked passed.

<Screenshot name="verify-checking" alt="Verify in the App while the agents check: the project checks, the independent review and the fix rounds" caption="An example task in a fictional project." />

## The checks {#lanes}

Project commands and scans produce recorded results:

<CardGroup cols={2}>
  <Card title="Project checks" icon="square-terminal">Tests, types, lint and build run on the commit. A failure is recorded, and the reviewer rules on it.</Card>
  <Card title="Code health" icon="badge-check" href="/docs/reference/code-health">Complexity and duplication in the files your agent changed, fed back to it after each turn.</Card>
  <Card title="Security scans" icon="shield-check" href="/docs/reference/code-health#security-scans">Secrets, dependency advisories, GitHub workflows and risky code. An unavailable scan stays **not checked**.</Card>
  <Card title="Recorded proof" icon="file-text">A point passes only with evidence: a check's output, a captured response, a screenshot or a file.</Card>
</CardGroup>

Separate agents review the code and its behavior:

<CardGroup cols={2}>
  <Card title="Independent review" icon="shield-check" tone="verify">Reads the whole diff, adds missing tests, runs each **Done means** step and compares screens with their artifacts. A small task gets one reviewer.</Card>
  <Card title="Security review" icon="key-round">When the change crosses a trust boundary or edits agent controls. Your agent fixes critical and high findings first.</Card>
  <Card title="Design review" icon="shapes">Checks each finished design before you see it, unless you turn **Design review** off in [Settings](../reference/settings.mdx#workflow).</Card>
  <Card title="Second opinion" icon="network">A reviewer from another agent family checks risky changes [when enabled](../reference/settings.mdx#second-opinion), or on request. Findings are **Taken** or **Kept**.</Card>
</CardGroup>

<Note>With **Independent review** off in [Settings](../reference/settings.mdx#independent-review), no fresh agent checks the change, and Verify shows it as **skipped**.</Note>

## Two fix rounds {#rounds}

A review fails on a **Done means** point, a red check, a critical or high security finding, lost data, or a bug it reproduces in the changed lines. Your agent fixes it and commits; a fresh reviewer rechecks what failed and what the fix changed. That can happen twice, and a round that fixes nothing ends them early.

## When the checks cannot finish {#when-it-stops}

Some failures end the checks: a point still failing after the second round, a prerequisite only you can supply, or an unavailable environment. You get one question: change what **Done means** says, ask for one more fix round, or stop the task. Work outside the task becomes a follow-up with its owner. No answer marks a failing point as passed.

## Read the code {#code}

<Screenshot name="verify-review" alt="Review the code: the file tree and the diff of the example task" />

**Review the code** opens the file tree and a **Unified / Split** diff. **Viewed** saves your reading progress; **All viewed** and **Clear** apply to every file.

### Ask about any line {#line-comments}

Select a line and choose **Ask agent**. Conversation opens an editable draft with the file, revision and selected lines. Sending it never approves the change or allows a push.

### Findings from the agents {#findings}

Security and second-opinion findings appear on their lines. Request a change, or record why a finding is not a problem; the reason becomes a [project lesson](../memory.mdx) for later reviews.

### Ask another reviewer {#another-reviewer}

**Ask another reviewer** picks an installed agent that did not build the change. It reviews one file or all files, edits nothing and stops after 8 minutes.

## Approve {#approve}

Approve the whole change in the page header, also when its agent has stopped. Your approval always saves, even when the code moved after the checks or a recheck is running.

<CardGroup cols={3}>
  <Card title="Approve" icon="badge-check" tone="verify">Nothing is pushed. The conversation stays open for merge, deploy and tweaks.</Card>
  <Card title="Approve and create PR" icon="git-pull-request">Pushes the task's branch and opens the [pull request](pull-request.mdx). Needs `gh`.</Card>
  <Card title="Copy the git commands" icon="clipboard">The commands to push and merge yourself.</Card>
</CardGroup>

### After you approve {#after-approve}

Ask your agent to merge, push, deploy or run end-to-end tests; each still needs your request.

| Verify shows | What you do |
| --- | --- |
| **Not merged yet** | Merge as usual. Merged on the web? Pull the base branch, or press **Mark as merged** |
| **1 change since your approval** | Your agent committed a tweak. Press **View the change**, then **Approve change** in the header. With an open pull request, your merge accepts it |
| **Merged into main** | The task is in **Shipped**. New work starts with **Start a follow-up** |

QualityLayer recognizes local merges, including squash and rebase, and pull requests it opened on GitHub. For work built directly on main, only that task's fixes count ([details](implement.mdx#where-it-lands)).
