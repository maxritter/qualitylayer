Purpose
The first of three steps. The agent reads the code, asks you what only you can answer, and writes one Plan. It is the only page you read and approve before the build, and the page that goes to GitHub as a pull request when others approve it.
Drawn from
The sample task Use QualityLayer from your agent, without the App. The parts on the page are the model's own markup, the App's diagram view and its preview cards.
Assumed
The task's sentences are a sample. The Summary's two lines, the three lines that open Approach and the three findings under Reviews are made up to show those parts. Controls work here; nothing is sent or saved.

In short

One page and two files. Summary, Done means and Approach are always there; every other section appears only when it has something to say.

  • One step, one page, two files. The agent reads, asks and writes in one go; you answer questions and approve once
  • Summary: what you get, in one or two lines. The outcomes are the Done means points, so the Summary does not list them
  • Problem is the second section: who has it, what it costs, what is missing
  • Done means, with its proof. A row is a point; it opens to how it shows and the steps that prove it. The heading says how it will be proven. Verify shows the same rows as they ran. A point is something a user can observe
  • Scope has two columns, In scope and Out of scope
  • Approach. Three lines first: what was chosen, what it gives, what it costs. Then at most five bullets of what changes
  • Decided with you and Decisions made for you: one list each, in one group of folds, with Change on every answer
  • The agent reads the code while the page fills in. The Plan's header says so. Current system is a Technical fold; the findings are in the agents' file, one line each. What a finding means for you shows up as a Done means point, a Scope line or a question
  • Technical: four closed folds, the ones a person has to agree with or live with: Current system, Data and interfaces, Engineering decisions, Assumptions. What only the build needs (internal contracts, the check commands, what to read first, pitfalls) is in the agents' file. A contract a caller meets, such as an API or a command, is an Interface tab
  • No file table. File paths live on the build's task cards only: each fact sits in one section
  • Pull request in the header, GitHub only: a click pushes the Plan on its own branch and opens GitHub's compare page, prefilled; you create the pull request there. Approvals and every comment come back to this page. Approved here instead, the request gets "Approved in QualityLayer by @you", closes, and its branch is deleted.
