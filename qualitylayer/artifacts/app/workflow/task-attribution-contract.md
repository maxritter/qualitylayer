# Observe the task the session joined

An explicit workflow session binding names the task whose Plan, Implement and
Verify records the agent updates, even when the native process started in a
different checkout. The task keeps its recorded target checkout. Native cwd is
path and native-message proof context; it never selects another task merely because a hook runs there.
CLI execution retains its existing explicit-checkout behavior. A recorded
checkout must still resolve through the existing cached Git discovery to the
same project common directory; a reused path cannot select the old task.

Cost assignment starts at the session's recorded task claim and ends at its next
assignment. Exact native session identities and helper lineage determine which
records belong. Lead calls follow the task's recorded stages; helper costs keep
their existing starting-step allocation. Pre-claim history, unrelated sessions
and repeated parent/helper receipts do not inflate totals.

Observation uses a derived local current-binding index validated against the
authoritative per-project workflow binding. Its generation, adoption and
retirement follow that binding; wall-clock age alone cannot discard an active
agent. Existing sessions recover through their exact bounded assignment records.
Ambiguous or invalid records grant no ownership. No per-hook project/transcript
inventory, new poller, model instruction, approval or automatic task launch is
introduced.

The derived index uses the existing 512 native-session bound. New admission may
prune demonstrably orphaned entries; it preserves active authority and refuses
an all-active full directory before publishing a new session claim. Existing
keys remain rebindable. Explicit assignment changes release the same native
session's prior project membership; ordinary observations never inventory
projects. Failed publication restores prior metadata or reports the incomplete
assignment, and never reports tracking as established.

Prompt and pending-answer observation follow the same validated task binding;
the native record must still prove the person’s words.

Hook path interpretation stays in native cwd, while Git and edit journals use
the bound task checkout. Only B's attributable changes enter B's App view. The
existing file/commit evidence and permission boundaries remain in force.

Plan → Implement → Verify journeys, exact B native file receipts, B shell hints
under existing evidence limits, progress, live outside status and priced costs
through reload. Installed prompt/live/activity hooks run under an owned process
with synthetic native records; this is not a paid provider/model session. The
actual CLI also refuses full active storage without replacing its previous
binding, build lead or session. App Model `task-attribution-parity.json` binds
this repair to the compiled source and captures; unrelated planned page gaps
remain unchanged.
