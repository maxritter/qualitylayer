# Guided setup on the selected machine

Approved 16 November 2026 in the Machine Center design, source revision `75445da8a5ad7345e3ce5563032658adc48ddfbd38f0ba2355b12af811607ee4`. Implementation and qualification are pending. Existing machine pairing remains unchanged.

The paired machine's Setup page offers its supported native agents. A documented direct installer runs only after the person chooses Install. Sign in opens the agent's own authentication flow in that machine's terminal. Unavailable direct operations retain official setup guidance; no guessed authentication argument becomes a model prompt.

Commands, platform and native home derive from the target server and its reviewed capabilities, not the browser's operating system or a supplied command string. Setup reuses the normal owned terminal host, attachment, Stop and generation checks. It adds no global terminal dock, credential copy, profile fork, provider-setting override or installer framework. Task and artifact terminals retain their existing checkout restrictions.

Closing the terminal view retains the operation and output. Cancel explicitly stops that operation and never marks an account signed in. Exit alone also proves no installed or signed-in state: native version and read-only account checks provide those facts. Unknown remains unknown. Native account secrets stay in the agent's own terminal and store. Model example controls stay model-only.

One usable agent is enough; others may remain uninstalled. Known signed-out agents offer their native sign-in. An agent whose authentication cannot be reported retains its existing launch capability without claiming a signed-in account. Native permissions and the two workflow approvals keep their owners.

The existing CLI pairing prompts preserve UTF-8 passwords and challenge codes, including non-ASCII characters. Hidden input stays hidden. Each prompt restores terminal echo and closes its own terminal handle after success or failure; the caller's standard input and SSH authentication authority keep their existing owners.

Projects come from the selected server's history or a folder validated there. A framed remote page does not open the host's folder picker. Start a task opens the existing New task card on this machine with the chosen project, checkout and usable agent. It starts no agent and approves no Plan.

The approved installing, sign-in, ready/project and first-task pages use the current Setup shell and controls. On compact layouts an opened terminal receives focus and scrolls into view. Source parity, successful isolated install/sign-in, cancellation, target-machine authority and resource checks are required before these pages become built.
