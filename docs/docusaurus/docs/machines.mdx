## Add a machine {#second-machine}

<span id="dev-containers"></span>

<Tabs groupId="machine">
  <Tab value="mac-mini" label="Mac Mini or server">

<Steps>
  <Step title="Turn on ssh">
    <Tabs groupId="os">
      <Tab value="macos" label="macOS">**Remote Login** under System Settings › General › Sharing. It is the one switch you make by hand.</Tab>
      <Tab value="linux" label="Linux">Install `openssh-server`.</Tab>
    </Tabs>
  </Step>
  <Step title="Add it in the App">**Settings › Machines › Add machine**, or **Add machine** in the sidebar's switch. Under **Computer**, type `user@host` (`user@host:port` works), or pick a Mac from **Nearby** or a host from your ssh config, then **Add**.</Step>
  <Step title="Let it pair">One progress view runs the steps: Reachable, Key, ssh config, System, QualityLayer, Licence, Connect. **Hide** keeps it going; **Settings › Machines** shows it again with **Show**.</Step>
  <Step title="Give the password once, if asked">If the machine accepts no key of yours, QualityLayer makes `~/.ssh/qualitylayer_ed25519` and asks for the machine's password once, in a sheet that shows the host key it trusts. The password goes straight to ssh and is never stored. A machine that takes keys only shows a `ssh-copy-id` command to run once, then **Done · try again**.</Step>
  <Step title="Sign in to your agent">On the machine, start your coding agent once and sign in.</Step>
  <Step title="Open it">**Open mac-mini** when the pairing is done. On its Setup page, type your project's path, such as `/Users/you/code/api`.</Step>
</Steps>

<Note>If your own key already works, nothing is asked. Pairing writes only the host key it showed into `known_hosts` and one marked `Host` block per machine into `~/.ssh/config`.</Note>

  </Tab>
  <Tab value="dev-container" label="Dev container">

<Steps>
  <Step title="Start the container">**Reopen in Container** in VS Code, or `devcontainer up --workspace-folder .` with the [Dev Container CLI](https://github.com/devcontainers/cli). QualityLayer never starts or rebuilds containers.</Step>
  <Step title="Add it in the App">**Add machine › Dev container** lists the running containers from Docker Desktop, OrbStack, Colima or Podman. One that publishes ssh (container port 2222 or 22) adds with **Add**, without a password.</Step>
  <Step title="Give it ssh, if it needs it">A container without ssh shows **Needs ssh** with the lines to copy into its `devcontainer.json`: the sshd feature, a free port and a volume for its home. Rebuild it, then **Add**.</Step>
  <Step title="Sign in to your agent">Inside the container, as on any computer, then add `/workspaces/api` on its Setup page.</Step>
</Steps>

<Tip>A rebuilt container pairs again by itself.</Tip>

  </Tab>
</Tabs>

## Remove a machine {#remove}

Under **Settings › Machines**, choose **Remove**. **Remove QualityLayer's key from it and its ssh config entry here** is on; tick **Also release its licence**, so the machine stops counting against your licence. Do this before you delete a container.

## When something is off {#troubleshooting}

A step that fails shows its cause and its fix in the progress view; **Try again** resumes there. For a machine already added:

| What you see | What to do |
| --- | --- |
| **No answer since 14:02 · Next try in 0:45** | Wait, or choose **Try now**. |
| **Key refused** | **Pair again**. |
| **Host key changed** | Compare the new fingerprint it shows, then **Trust new key**. |
| The agent waits at "Trust this folder?" | Answer in the task's Terminal pane in the App, or in your own session on the machine. Each agent asks once per folder. |
| An agent shows **Not installed** or not signed in on the machine's Setup page | Install or sign in to it on the machine, then choose **Check again**. |

By command, `qualitylayer machines add user@host` asks for the password hidden, and a script pipes it with `--password-stdin`; `qualitylayer machines add --container <name>` adds a dev container ([all machine commands](reference/commands.mdx#machines)).
